# Рейтинг и стоп-факторы

## Принцип оценки

Неделя 4 добавляет 30 баллов и доводит накопительный максимум курса до 100. Точные критерии и evidence заданы `contracts/course-1/week-4-score-manifest.json`. Критерий получает полный вес либо 0; ошибка trusted infrastructure не считается дефектом решения.

На неделе 4 контракт `diagnostics.stalled` входит в проверку actions и воспроизводимости открытых тестов; результат отражается в отчёте технического соответствия. Веса критериев, максимум 100 и перечень стоп-факторов сохраняются.

Стоп-фактор применяется независимо от числовой суммы и исключает решение из итогового топ-10 до устранения.

Учебный зачёт `learning-outcome.1` отделён от полного технического соответствия.
Обязательны воспроизводимость, архитектура, работающие процессы, единственность эффекта,
доказательство финала, полномочия, согласованная история, долговечная доставка и аварийное
восстановление недели 4. Частное отклонение формата снижает балл; отказ в зачёте требует
доказанного нарушения одного из этих условий. Непроверенное критическое свойство даёт
«Недостаточно данных». Каждый недостаток и стоп-фактор классифицируется по последствию.

## Стоп-факторы

Внутренняя диагностика недель 3–4 дополнительно оценивает готовность сдачи по
[политике late-week-quality.3](review-calibration-weeks-3-4.md): веса A/B/C/D —
30/35/25/10 и 40/25/25/10. Блокирующее недокументированное вмешательство в запуск
ограничивает оценку значением 60, доказанный повтор ранее доставленного замечания — 45.
Канонический manifest и учебный зачёт считаются отдельно; ошибки инфраструктуры не штрафуются.

| Стоп-фактор | Причина |
|---|---|
| Контур не запускается по README | Результат невоспроизводим |
| Основной API или worker реализован не на C# | Не выполнена обязательная технологическая часть курса |
| Авторитетное состояние находится не в PostgreSQL | Не проверяется основная среда курса |
| Предметные endpoints реализованы отдельными C#-контроллерами без каталога PostgreSQL actions | Не создан аналог Оркестратора |
| Клиент может выбрать БД, схему, функцию или SQL | Оркестратор допускает произвольное привилегированное выполнение |
| Процесс жёстко зашит одной последовательностью | Не создан WCF-подобный механизм |
| Для второго процесса в ядро добавлена ветка по имени карты | Не доказано повторное использование платформы |
| Повтор создаёт новый предметный эффект | Нарушена идемпотентность |
| Старый worker может завершить job после потери lease | Нарушена конкурентная корректность |
| Клиент может установить финальный успех | Нарушена граница доверия |
| Состояние и событие расходятся | Нет транзакционной целостности |
| Неверная квитанция завершает операцию | Внешним данным доверяют без проверки |
| Исходящий запрос теряется при сбое | Контур неустойчив |
| Ожидающий процесс теряется после перезапуска | Состояние процесса не является долговечным |
| Нет истории шагов и попыток | Выполнение невозможно доказать и расследовать |
| Скрытый action или workflow-карта требуют пересборки API/worker | Runtime не является универсальным |
| Python integration services отсутствуют, используют готовый image или владеют предметным состоянием | Не выполнена обязательная мультиплатформенная и интеграционная часть контура |
| В репозитории или журналах есть секреты | Нарушены требования безопасности |

## Проверка без защиты

Оцениваются код, данные, tests, документация и воспроизводимый black-box результат. Промпты, AI-история, количество коммитов, строки кода и обязательная устная защита не оцениваются.
